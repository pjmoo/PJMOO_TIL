## 1. 오늘 배운 핵심

- AI 개발 도구의 행동 규칙, 반복 작업 절차, 이벤트 자동화를 파일로 관리할 수 있다.
- 의존성과 설정이 존재한다는 사실은 기능 구현이나 연결 성공을 의미하지 않는다.
- Spring Security의 공개 경로는 실제 `SecurityFilterChain`을 기준으로 확인한다.
- 컨트롤러의 뷰 이름 반환과 HTML 템플릿 제공은 별도 작업이다.
- 컨텍스트 로딩, 빈 생성, 외부 서비스 연결, 실제 기능 검증은 서로 다른 테스트 범위다.
- pgvector가 설치된 이미지와 DB에서 확장이 활성화된 상태를 구분한다.

### Rules: 협업 기준을 파일로 남기기

원본 `CLAUDE.md`에는 말투와 모델·effort 제안, 작업 시작 전 합의에 관한 규칙이 있다. 이는 이 저장소가 정한 협업 방식이며 모든 AI 도구의 공통 동작이나 모델을 실제로 변경하는 자동화는 아니다. `AGENTS.md`는 `CLAUDE.md`를 가리키고 있다.

**배운 점:** 대화에서만 정한 기준보다 파일에 기록한 기준을 다음 세션에서 다시 확인하기 쉽다. 다만 규칙의 목적과 적용 도구를 명확히 해야 한다.

### Skills: 커밋과 프레임워크 사용 기준

원본에는 두 개의 스킬이 있다.

- `commit-convention`: `<영어 category> : <한글 설명>` 형식으로 커밋 메시지를 작성한다.
- `spring-boot-4`: 이 프로젝트 버전의 스타터, 보안 DSL, null 처리 등의 사용 기준을 정리한다.

커밋 형식 예시:

```text
docs : OAuth2 설정과 인프라 검증 범위 정리
```

스킬의 내용도 검토 대상이다. 예를 들어 `javax.*` 전체를 기계적으로 `jakarta.*`로 바꾸면 안 된다. Jakarta EE 관련 패키지의 전환과 Java SE의 `javax.sql.DataSource` 같은 타입은 구분한다.

| 이벤트 | 현재 설정에서 기록하려는 내용 |
| --- | --- |

명령형 Hook은 표준 입력으로 전달된 JSON을 읽는다. 원본은 셸과 `jq`로 값을 꺼내 `claude.log`에 추가한다. [Claude Code Hooks 공식 문서](https://code.claude.com/docs/en/hooks-guide)

처리 흐름은 `이벤트 → JSON 입력 → 필요한 필드 추출 → 로그 추가`다. 이 저장소의 명령 끝에는 `2>/dev/null || true`가 있어 기록 실패가 드러나지 않을 수 있다. 따라서 로그 파일이 완전한 감사 기록이라고 단정하지 않는다. 프롬프트·명령·응답 일부에는 인증 정보가 들어갈 수 있으므로 이번 TIL에는 실제 로그 내용을 복사하지 않았다.

## 4. 실제 SecurityFilterChain 읽기

[SecurityConfig.java](https://github.com/pjmoo/260915_cc/blob/8506b41288c2541ac6af2e77e8326694a342168e/src/main/java/org/example/cc/config/SecurityConfig.java)의 핵심 코드다.

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(authorize -> authorize
            .requestMatchers("/", "/error", "/actuator/health", "/actuator/info").permitAll()
            .anyRequest().authenticated())
        .oauth2Login(Customizer.withDefaults())
        .logout(logout -> logout.logoutSuccessUrl("/"));

    return http.build();
}
```

| URL | 현재 접근 규칙 |
| --- | --- |
| `/`, `/error` | 인증 없이 접근 허용 |
| `/actuator/health`, `/actuator/info` | 인증 없이 접근 허용 |
| `/swagger-ui.html`, `/api-docs` | 별도 공개 규칙이 없어 인증 필요 |
| `/actuator/prometheus` | 노출 설정에는 포함되지만 인증 필요 |
| 그 밖의 요청 | 인증 필요 |

**엔드포인트 노출과 접근 허용은 다르다.** Actuator의 `exposure.include`에 있다고 자동으로 공개되는 것은 아니다. `permitAll()`도 해당 URL의 구현이나 정상 응답까지 만들어 주지 않는다.

OAuth2 로그인은 등록된 공급자 설정을 사용한다. 기본 로그인 페이지에는 구성된 클라이언트로 인증을 시작할 링크가 제공될 수 있다. [Spring Security OAuth2 로그인 문서](https://docs.spring.io/spring-security/reference/servlet/oauth2/login/advanced.html)

## 5. HomeController와 뷰 템플릿

```java
@Controller
public class HomeController {

    @GetMapping("/")
    public String home() {
        return "home";
    }
}
```

`@Controller`에서 반환한 `"home"`은 응답 본문 문자열이 아니라 뷰 이름이다. 현재 구성에서는 `templates/home.html` 같은 템플릿이 필요하지만 해당 파일이 없다. 따라서 `/`가 공개되어 있어도 정상 HTML 화면이 나온다고 볼 수 없다.

**배운 점:** 보안 통과 → 컨트롤러 실행 → 뷰 해석 → 응답 생성의 각 단계를 따로 확인한다. 이 문서에서는 누락을 기록했으며 애플리케이션 기능을 추가하지 않았다.

## 6. 환경변수와 인프라 준비 조건

[application.yaml](https://github.com/pjmoo/260915_cc/blob/8506b41288c2541ac6af2e77e8326694a342168e/src/main/resources/application.yaml)의 주요 외부 입력이다.

| 변수 | 용도 | 기본값 여부 |
| --- | --- | --- |
| `DB_NAME` | PostgreSQL DB 이름 | `cc` |
| `DB_USERNAME`, `DB_PASSWORD` | DB 계정 | 둘 다 `postgres` |
| `REDIS_HOST`, `REDIS_PORT` | Redis 접속 | `localhost`, `6379` |
| `GOOGLE_OAUTH2_CLIENT_ID` | Google OAuth2 클라이언트 ID | 없음 |
| `GOOGLE_OAUTH2_CLIENT_SECRET` | Google OAuth2 클라이언트 비밀값 | 없음 |
| `GOOGLE_GENAI_API_KEY` | Google GenAI 호출 키 | 없음 |

DB URL은 `jdbc:postgresql://localhost:5432/${DB_NAME:cc}`다. DB 계정의 기본값은 개발 편의용으로 해석한다. 환경변수 파일을 만든 것만으로 실행 프로세스에 자동 전달되는 것은 아니므로 셸·IDE의 실행 설정을 확인한다.

### JPA와 pgvector의 스키마 설정은 별개

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: validate
  ai:
    vectorstore:
      pgvector:
        index-type: HNSW
        distance-type: COSINE_DISTANCE
        dimensions: 768
        initialize-schema: true
        schema-name: public
        table-name: vector_store
```

- JPA `validate`: 엔티티와 DB 스키마를 검증하는 설정이며 테이블을 자동 생성하는 설정이 아니다.
- pgvector `initialize-schema: true`: 벡터 저장소에 필요한 스키마 초기화를 요청한다. DB 연결과 권한이 필요하다.
- `HNSW`: 벡터 유사도 검색용 인덱스 방식.
- `COSINE_DISTANCE`: 벡터 간 비교에 사용할 거리 기준.
- `768`: 저장할 벡터의 차원 수. 실제 임베딩 출력 차원과 맞아야 한다.

이 프로젝트는 채팅 모델 `gemini-2.5-flash`, 임베딩 모델 `text-embedding-004`를 설정한다. 이는 저장소의 선언값이며 실제 제공 여부와 호출 가능 여부는 별도 확인 대상이다. [Spring AI pgvector 문서](https://docs.spring.io/spring-ai/reference/api/vectordbs/pgvector.html)

### pgvector 이미지 설치와 활성화 구분

원본 README의 “pgvector 이미지면 `CREATE EXTENSION` 없이 바로 사용” 설명은 구분이 필요하다. 이미지는 확장 파일을 제공하지만 사용할 DB에서 확장을 활성화해야 한다. 애플리케이션의 스키마 초기화가 이를 수행할 수 있어도 확장 활성화 단계 자체가 사라지는 것은 아니다. [pgvector 공식 README](https://github.com/pgvector/pgvector#installation)

DB에서 상태를 확인하는 SQL 예시:

```sql
SELECT extname, extversion
FROM pg_extension
WHERE extname = 'vector';

-- 확장이 설치되어 있고, 필요한 권한을 가진 계정에서 활성화할 때
CREATE EXTENSION IF NOT EXISTS vector;
```

검토한 저장소에는 Compose 파일이 없으므로 “현재 Compose로 DB와 Redis를 실행할 수 있다”고 기록하지 않는다.

## 7. 테스트가 보장하는 범위

현재 테스트는 다음과 같다.

```java
@SpringBootTest
class ApplicationTests {
    @Test
    void contextLoads() {
    }
}
```

테스트 본문이 비어 있어도 Spring 컨텍스트 로딩 중 문제가 발생하면 실패한다. 다만 Redis 명령이나 AI API를 실제로 호출하는 검증은 없다.

| 검증 수준 | 확인 가능한 것 | 그것만으로 보장하지 못하는 것 |
| --- | --- | --- |
| 컨텍스트 로딩 | 애플리케이션 설정 조합의 초기화 | 모든 외부 서비스의 실제 기능 |
| 빈 주입 후 null 확인 | 객체 생성·주입 여부 | 네트워크 왕복과 인증 성공 |
| DB 쿼리·Redis PING | 해당 연결과 기본 명령 | 로그인·RAG 전체 동작 |
| 실제 OAuth2·AI·검색 요청 | 해당 시나리오 동작 | 다른 예외 상황 전체 |

README에 나오는 `DataSource`, `RedisConnectionFactory`, `ChatModel`, `EmbeddingModel`, `VectorStore` 주입 검증은 현재 테스트에 구현되어 있지 않다. 또 연결 팩토리 생성만으로 Redis가 실행 중인지 확인했다고 볼 수 없다.

DB 스키마 초기화나 Hibernate 설정 때문에 컨텍스트 로딩에 외부 DB가 필요할 수 있다. 이번 문서화 작업에서는 DB·OAuth2·AI 인증 정보를 준비해 애플리케이션 테스트를 실행하지 않았다.

## 8. Git 협업에서 배운 점

- `remote add`와 `fetch`는 다른 원격 이력을 비교할 때 유용하다. `fetch` 자체는 워킹트리를 바꾸지 않는다.
- 별도 디렉터리의 `clone`은 독립 작업 공간이 필요할 때 유용하다. 어느 방법이 항상 더 안전하다고 일반화하지 않는다.
- `git stash push -u`는 추적 파일 변경과 미추적 파일을 보관하지만 **ignored 파일은 포함하지 않는다**.
- `git switch --detach <commit>`은 브랜치 이름 대신 커밋을 직접 체크아웃한다. 새 작업을 남기려면 브랜치를 만들어 커밋을 연결하는 편이 명확하다.
- 원래 브랜치로 돌아오는 것과 stash를 복원하는 것은 별개다. 필요한 변경은 `stash apply` 또는 `stash pop`으로 복원한다.

## 10. 복습과 다음 확인 항목

1. **의존성이 있으면 기능도 완성된 것인가?** 아니다. 실제 구현과 호출 결과를 확인해야 한다.
2. **`permitAll()`이면 HTTP 200인가?** 아니다. 뷰 누락이나 처리 오류는 별도 문제다.
3. **빈이 만들어졌으면 외부 연결도 정상인가?** 아니다. 실제 명령이나 요청으로 검증한다.
4. **JPA `validate`인데 pgvector 초기화가 가능한 이유는?** 서로 다른 구성 요소의 스키마 설정이기 때문이다.
5. **Hook과 Skill의 차이는?** Hook은 이벤트 명령이고 Skill은 작업 절차·지식이다.

다음 구현·검증에서는 홈 템플릿 제공, 필요한 공개 경로 확정, DB·Redis 준비, OAuth2 로그인, 임베딩 차원과 검색 결과를 순서대로 확인할 수 있다.
