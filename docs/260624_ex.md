## 🛠 배운 핵심 개념 (What We Learned)

- **다형성 (Polymorphism)**: 하나의 객체가 여러 가지 타입의 옷을 입을 수 있는 성질로, 상위 타입 변수에 여러 하위 자식 객체를 유연하게 대입해 조작하는 원리를 배웁니다.
- **인터페이스 (interface)**: 오직 핵심 규약(상수와 추상 메소드)만 선언해 둔 설계도로서, 다양한 구현체들이 이 규약을 완벽히 구현하여 조립 가능한 웹 설계를 실현하도록 돕는 필수 도구입니다.

### 캡슐화는 변경 규칙을 지키게 하는 설계

필드를 private으로 숨겨도 모든 값을 자유롭게 바꾸는 setter를 제공하면 업무 규칙을 지키기 어렵다. 캡슐화는 객체가 유효한 상태를 유지하도록 변경 경로를 통제하는 것이다. 상속은 코드 재사용뿐 아니라 부모 타입의 약속을 자식이 지킨다는 관계를 전제로 한다.

**예시로 이해하기:** 포인트를 임의의 숫자로 덮어쓰는 setter 대신 적립·사용 메서드에서 음수와 잔액 부족을 검사할 수 있다. 단순히 다른 객체의 기능을 이용하는 관계라면 상속보다 필드로 보유하는 합성이 변경 영향을 줄일 수 있다.

### 인터페이스와 다형성으로 변경 지점 나누기

인터페이스는 호출자가 기대하는 동작의 계약이다. 구현체를 인터페이스 타입으로 다루면 호출 코드가 구체 클래스 이름에 덜 의존하고, 오버라이딩된 인스턴스 메서드는 실제 객체에 따라 실행된다. 다운캐스팅은 객체의 실제 타입이 맞아야 한다.

**예시로 이해하기:** 결제 서비스가 PaymentGateway 계약을 받도록 하면 카드 결제와 테스트용 구현체를 같은 호출 방식으로 사용할 수 있다. 제네릭은 이와 별도로 컬렉션 등에 들어갈 타입을 컴파일 단계에서 제한해 잘못된 형변환을 줄인다.
