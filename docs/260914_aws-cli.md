# AWS CLI로 ARM EC2에 Docker 애플리케이션 배포

> 학습일: 2026-09-14  
> 참고 자료: AWS 클라우드 기초·환경 설정, AWS EC2 배포·Docker 설치·Aiven DB 연동

## 배운 내용

AWS는 관리 범위에 따라 IaaS, PaaS, SaaS로 나눌 수 있다. EC2와 VPC는 OS와 네트워크까지 직접 관리하는 IaaS이고, Aiven은 DB를 제공하는 PaaS에 가깝다. AWS 리전 안에는 여러 가용 영역(AZ)이 있으며, 장애 대응에는 Multi-AZ 구성이 사용된다.

EC2는 AMI, 인스턴스 타입, EBS, ENI로 구성된다. 보안 그룹은 상태 저장 방화벽이므로 필요한 포트만 연다. 실습에서는 SSH(22)는 현재 공인 IP에만 허용하고, HTTP(80)와 Spring Boot(8080)는 외부 요청을 허용했다.

## SSO 인증

IAM Identity Center(SSO)는 MFA 뒤에 임시 자격 증명을 발급한다.

~~~
aws configure sso --profile studentXX
aws sso login --profile studentXX
export AWS_PROFILE=studentXX
export AWS_REGION=ap-northeast-2
export AWS_PAGER=
aws sts get-caller-identity
~~~

SSO 토큰이 만료되면 aws sso login을 다시 실행한다. 자격 증명 오류가 나오면 프로필과 로그인 상태를 먼저 확인한다.

## EC2 생성 흐름

1. 기본 VPC를 조회한다.
2. 보안 그룹을 만들고 22, 80, 8080 포트를 설정한다.
3. EC2 키 페어를 생성하고 PEM 파일 권한을 chmod 400으로 제한한다.
4. Parameter Store에서 Ubuntu ARM64 AMI를 조회한다.
5. t4g.nano를 생성하고 waiter로 running, 2/2 status ok 상태를 기다린다.
6. 공인 IP로 SSH 접속해 uname -m이 aarch64인지 확인한다.

Spring Boot와 Docker를 함께 실행할 때는 512MiB인 t4g.nano보다 1GiB인 t4g.micro가 안정적이다. 인스턴스를 중지한 뒤 타입을 변경하고 다시 시작할 수 있다.

~~~
aws ec2 modify-instance-attribute \
  --instance-id "$INSTANCE_ID" --instance-type "Value=t4g.micro"
aws ec2 start-instances --instance-ids "$INSTANCE_ID"
aws ec2 wait instance-status-ok --instance-ids "$INSTANCE_ID"
~~~

## ARM Docker 이미지

t4g 인스턴스는 ARM64(aarch64)이므로 x86 이미지 전용으로 빌드하면 exec format error가 발생한다. GitHub Actions에서 Docker Buildx로 두 플랫폼을 함께 빌드한다.

~~~yaml
- uses: docker/setup-buildx-action@v4
- uses: docker/build-push-action@v7
  with:
    push: true
    platforms: linux/amd64,linux/arm64
    tags: ghcr.io/<owner>/simple-back:latest
~~~

EC2에는 Docker를 설치한 뒤 GHCR에서 이미지를 pull한다. Aiven 접속 정보는 aiven.env로 주입하고, --restart unless-stopped로 Docker 재시작 시 컨테이너를 자동 복구한다.

~~~
sudo docker run -d --name simple-back --restart unless-stopped \
  -p 8080:8080 --env-file aiven.env \
  ghcr.io/<owner>/simple-back:latest
~~~

/와 /users가 200을 반환하고 /users에서 Aiven MySQL 데이터를 읽으면 연결이 완료된 것이다. 문제 발생 시 보안 그룹 규칙, sudo ss -tulnp, sudo docker logs 순서로 확인한다.

## 정리

실습이 끝나면 비용이 발생하지 않도록 EC2를 중지한다. stop은 EBS를 보존하지만 공인 IPv4가 바뀔 수 있다. 고정 IP가 필요하면 Elastic IP를 사용한다. 비밀번호·DB URL은 Git 저장소와 셸 히스토리에 남기지 않아야 한다.

## 기존 README 명령어에서 확인한 포인트

- `AWS_PROFILE`, `AWS_REGION`, `AWS_PAGER`를 지정하면 같은 SSO 계정·리전을 사용하고 출력이 호출기에 멈추지 않는다. `aws sts get-caller-identity`로 현재 인증 주체를 먼저 확인한다.
- 보안 그룹은 특정 VPC에 속하므로 VPC ID를 먼저 조회한다. SSH(22)는 현재 IP(`/32`)로 제한하고, 생성 후 `describe-security-groups`로 포트와 CIDR을 재확인한다.
- 키 페어의 `KeyMaterial`은 생성 시 한 번만 반환된다. PEM 파일을 즉시 저장하고 `chmod 400` 또는 Windows `icacls`로 접근 권한을 제한한다.
- `run-instances` 직후에는 SSH가 준비되지 않을 수 있다. `instance-running`과 `instance-status-ok`를 모두 기다린 뒤 공인 IP를 조회한다.
- 실습 종료 시 컨테이너를 멈춘 후 EC2를 `stop`한다. `stop`은 EBS를 보존하지만 `terminate`는 인스턴스를 삭제한다.
