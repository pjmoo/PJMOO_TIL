# 데이터베이스 SQL 데이터 조작(DML) & 테이블 정의(DDL) 마스터 🛠

데이터베이스 테이블 자체를 만들고 수정하는 정의 언어(DDL)와 생성된 테이블 내의 실제 데이터를 조작(삽입, 수정, 삭제)하는 조작 언(DML)의 핵심을 학습합니다.

---

## 🛠 배운 핵심 개념 (What We Learned)

- **제약 조건 (Constraint)**: 기본키(`PRIMARY KEY`), 외래키(`FOREIGN KEY`), 중복 방지(`UNIQUE`), 필수 입력(`NOT NULL`) 등 올바른 데이터 규격을 정하는 규칙을 배웁니다.
- **트랜잭션 제어 (commit/rollback)**: 데이터 추가/수정을 마쳤을 때 실제 반영(`COMMIT`)하거나 잘못되어 되돌리는(`ROLLBACK`) 안전장치를 파악합니다.

---

2. 테이블 생성 DDL을 실행하고, DML 쿼리로 가상의 회원 데이터를 넣고 빼며 스키마와 데이터의 관계를 시각적으로 분석합니다.

### 변경 대상과 변경 결과를 함께 읽기

INSERT·UPDATE·DELETE는 저장된 데이터를 바꾼다. UPDATE와 DELETE의 WHERE는 변경 범위를 결정하므로 조회할 때의 조건과 같은 의미인지 먼저 확인해야 한다. 소프트 삭제는 행을 남겨두는 대신 조회·중복 검사·복원에서 삭제 상태를 일관되게 다루는 책임을 만든다.

**예시로 이해하기:** 학습용 변경문을 읽을 때 같은 조건의 SELECT가 어떤 행을 고르는지 예상하고 영향받는 행 수와 연결한다. is_deleted 같은 표시만 추가했다고 모든 조회에서 삭제 데이터가 자동으로 제외되는 것은 아니다.

### 제약조건과 인덱스는 목적이 다르다

제약조건은 저장해도 되는 데이터를 정하고 인덱스는 특정 조회를 빠르게 찾도록 돕는다. 인덱스가 늘면 저장 공간과 변경 시 유지 비용도 늘어난다. 기본키는 행 식별, 외래키는 참조 무결성, UNIQUE는 값의 중복 제한이라는 서로 다른 의도를 표현한다.

**예시로 이해하기:** 회원 ID를 인조키로 두더라도 이메일 중복을 허용하지 않는 업무 규칙에는 별도 유일성 제약이 필요하다. PDF의 DDL 커밋 설명은 DBMS별 차이를 고려해야 하며, 모든 DB에서 DDL은 절대 롤백할 수 없다고 일반화하지 않는다.
