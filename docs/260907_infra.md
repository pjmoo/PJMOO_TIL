# Docker와 Linux 기초 명령어 실습

> 2026-09-07에 Docker 컨테이너를 실행해 Ubuntu 환경에서 Linux 기본 명령어, 환경 변수, 파일 권한, 배포 스크립트 실행을 실습했다.

## Docker 기본 확인과 이미지 준비

```sh
docker -v
docker version
docker info

docker pull ubuntu:26.04
docker images
```

- `docker -v`: Docker의 간단한 버전을 확인한다.
- `docker version`: 클라이언트와 서버의 상세 버전을 확인한다.
- `docker info`: Docker 엔진, 컨테이너, 이미지 등의 현재 상태를 확인한다.
- `docker pull ubuntu:26.04`: Ubuntu 26.04 이미지를 내려받는다.
- `docker images`: 로컬 이미지 목록을 확인한다.

## 컨테이너 생성, 분리, 재접속

```sh
docker run -it --name linux-practice ubuntu:26.04 bash

# 컨테이너를 종료하지 않고 분리: Ctrl + P, Ctrl + Q
docker ps
docker attach linux-practice
```

- `docker run`: 컨테이너를 생성하고 실행한다.
- `-i`: 표준 입력을 유지한다.
- `-t`: 터미널을 할당한다.
- `--name linux-practice`: 컨테이너 이름을 지정한다.
- `docker ps`: 실행 중인 컨테이너를 확인한다. 종료된 컨테이너까지 보려면 `docker ps -a`를 쓴다.
- `docker attach`: 분리된 컨테이너의 터미널에 다시 연결한다.
- `docker rm linux-practice`: 중지된 컨테이너를 삭제한다.

## 패키지와 파일 시스템

```sh
apt update
apt install -y curl
curl --version

pwd
ls -la
mkdir /practice
cd /practice
```

- `apt update`: 설치 가능한 패키지 목록을 최신으로 갱신한다.
- `apt install -y curl`: 확인 질문 없이 curl을 설치한다.
- `pwd`: 현재 작업 경로를 출력한다.
- `ls -la`: 숨김 파일(`-a`)을 포함해 상세 정보(`-l`)를 출력한다.
- `mkdir`: 폴더를 만들고, `cd`는 폴더로 이동한다.

## 환경 변수와 파일 리다이렉션

```sh
export APP_ENV=development
export PORT=8080
printenv APP_ENV
echo $PORT

echo "APP_ENV=development" > app.env
echo "PORT=8080" >> app.env
cat app.env
```

- `export`: 현재 셸과 하위 프로세스에서 쓸 환경 변수를 설정한다.
- `printenv`, `echo $변수명`: 환경 변수 값을 확인한다.
- `>`: 파일을 만들거나 기존 내용을 덮어쓴다.
- `>>`: 파일 끝에 내용을 추가한다.
- `cat`: 파일 전체 내용을 출력한다.

## 배포 스크립트 다운로드와 검색

```sh
curl -L -o deploy.sh https://gist.githubusercontent.com/qus0in/d36165612fdfdb1e3622924ef37d6b46/raw/2d9424734b5f8ef8e8b6cd3871a0ce6740160b51/deploy.sh

head -n 3 deploy.sh
tail -n 3 deploy.sh
grep -n "echo" deploy.sh
cat deploy.sh | grep -i "server"
```

- `curl -L`: 리다이렉트된 주소도 따라가서 내려받는다.
- `-o deploy.sh`: 내려받은 내용을 지정한 파일 이름으로 저장한다.
- `head -n 3`, `tail -n 3`: 파일의 처음 또는 마지막 3줄을 확인한다.
- `grep -n`: 일치하는 줄과 줄 번호를 출력한다.
- `grep -i`: 대소문자를 구분하지 않고 검색한다.
- `|`: 앞 명령어의 결과를 다음 명령어의 입력으로 전달하는 파이프다.

## 실행 권한과 스크립트 실행

```sh
chmod +x deploy.sh
./deploy.sh

chmod 744 app.env
ls -l
```

- `chmod +x`: 파일에 실행 권한을 추가한다.
- `./deploy.sh`: 현재 폴더의 스크립트를 직접 실행한다. 실행 권한이 없다면 `sh deploy.sh`로 실행할 수도 있다.
- `chmod 744 app.env`: 소유자에게 읽기·쓰기·실행 권한(7), 그룹과 다른 사용자에게 읽기 권한(4)을 부여한다.
- `ls -l`: 권한 변경 결과를 확인한다.

## 정리

Docker 컨테이너는 격리된 Linux 실습 환경을 빠르게 준비할 수 있게 해 준다. 컨테이너 안에서 패키지 설치, 환경 변수 설정, 파일 작성, 텍스트 검색, 실행 권한 부여까지 기본적인 서버 작업 흐름을 한 번에 연습했다.

### 이미지·컨테이너·프로세스의 수명

이미지는 실행 환경의 바탕이고 컨테이너는 그 이미지로 만든 실행 인스턴스다. Linux 컨테이너는 커널의 namespace로 보이는 자원을 분리하고 cgroups로 자원 사용을 제어한다. Windows에서 Linux 컨테이너를 실행할 때는 Linux 커널을 제공하는 가상화 계층이 있어, Windows 커널을 그대로 공유한다고 설명하면 부정확하다.

현재 README의 `docker run -it ... bash`에서는 bash가 주 프로세스이므로 그 셸에서 `exit`하면 컨테이너도 종료된다. `attach`는 기존 주 프로세스에 다시 연결하고, `exec`는 실행 중인 컨테이너 안에서 별도의 명령을 시작한다. 따라서 `exec`로 연 보조 셸의 종료를 컨테이너 종료와 혼동하지 않는다. 정지된 컨테이너의 쓰기 레이어는 남지만 컨테이너 삭제 시에는 사라진다. 볼륨에 저장한 데이터는 컨테이너와 수명이 별개다.

### 리다이렉션·환경변수·권한을 읽는 기준

셸에서 `|`는 앞 명령의 표준 출력을 다음 명령의 표준 입력으로 전달한다. 표준 오류는 별도 통로라 기본 파이프에 함께 들어가지 않는다. `>`는 대상 파일을 덮어쓰고 `>>`는 끝에 추가한다. 로그가 화면에는 보이는데 파일에는 없으면 출력 통로가 stdout인지 stderr인지 먼저 구분한다.

Linux 셸의 `APP_ENV=dev`는 셸 변수 대입이고 `export APP_ENV=dev`는 이후 자식 프로세스로 전달할 환경변수 등록이다. 이미 실행 중인 다른 프로세스의 설정까지 소급 변경하지 않는다. `chmod +x`는 실행 권한을 추가하지만 파일 내용·인터프리터·경로 오류까지 해결하지는 않는다. 디렉터리의 `x`는 진입·경로 탐색 권한이며 파일의 실행 권한과 의미가 다르다. 이 설명과 아래 예시는 컨테이너 안의 Linux 셸 기준이다.

```sh
# 표준 출력으로 나온 로그 중 오류 문구를 포함한 줄만 확인
cat app.log | grep ERROR
# 현재 셸의 자식 프로세스에 값 전달
export APP_ENV=dev
printenv APP_ENV
```
